What is RDBMS?
 RDBMS stands for Relational Database Management System. It’s a software system used to create, store, manage, and manipulate data that is organized in tables (relations), manages data in tables that are related to each other using keys (Primary & Foreign Keys).

RDBMS vs DBMS (Database Management System) :

| Feature         | DBMS                 | RDBMS                             |
| --------------- | -------------------- | --------------------------------- |
| Structure       | Stores data as files | Stores data in tables (relations) |
| Relationships   | No relationships     | Tables related via keys           |
| Data Redundancy | High                 | Reduced via normalization         |
| Query Language  | No standard language | Uses SQL                          |
| Example         | MS Access            | MySQL, PostgreSQL, Oracle         |


Main Features of an RDBMS :

| Feature                 | Description                                |
| ----------------------- | ------------------------------------------ |
| Tables (Relations)      | Data is stored in rows and columns         |
| Relationships           | Connect multiple tables using keys         |
| SQL Support             | RDBMS uses SQL to interact with data       | [SQL -> Structure Query Language]
| Data Integrity          | Enforces accuracy using constraints        |
| Concurrency Control     | Many users can work simultaneously         |
| Security                | Access control and permissions             |
| Normalization           | Reduces redundancy and improves efficiency |


ACID Properties (Guarantees of RDBMS)
RDBMS ensures data reliability through ACID properties:

| Property        | Meaning                                        | Example                                             |
| --------------- | ---------------------------------------------- | --------------------------------------------------- |
| Atomicity       | Transaction is “all or nothing”                | If money transfers fail halfway, no data is updated |
| Consistency     | Database moves from one valid state to another | No invalid data is allowed                          |
| Isolation       | Transactions don’t affect each other           | Two users editing data won’t conflict               |
| Durability      | Once committed, data is permanent              | Even after a crash, data is safe                    |

Examples : Let’s say you have two tables:

1. Students Table

   | student_id | name  | class |
   | ---------- | ----- | ----- |
   |     1      | Alice |   10  |
   |     2      | Bob   |   10  |

2. Marks Table

   | mark_id | student_id | subject | marks |
   | ------- | ---------- | ------- | ----- |
   |    1    |      1     | Math    |   88  |
   |    2    |      2     | Science |   92  |

Observations:
 Both tables are related using the column student_id.
 student_id in students is the Primary Key.
 student_id in marks is the Foreign Key.That’s why it’s called a Relational Database — data in one table relates to data in another.
